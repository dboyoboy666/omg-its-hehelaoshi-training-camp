# 导航页视觉与特效 · 避坑指南

> 配套《导航页视觉与特效-SOP》使用。版本 v1.0（2026-10-16 蒸馏）
> 每条都是本项目实战踩过的坑，标注「坑象 / 真相 / 对策」。

---

## 一、选择器与结构坑

### 坑 1：标题逐字规则污染角标内层文字
- **坑象**：角标加进去后，里面「浦外」二字也被大标题的渐变裁字/浮动动画规则命中，字形全乱。
- **真相**：标题逐字拆分用的是 `.title span` 后代选择器，角标内层的 `<span>` 照样匹配。
- **对策**：标题 glyph 规则必须收紧为 **`.title > span`**（直接子选择器）；角标包裹用 `<b>` 不用 `<span>`，双保险。

### 坑 2：渐变填充与渐变字想放同一元素
- **坑象**：想让角标「框内填充是背景图水色渐变、字是标语橙渐变」，写一个元素套两个 background-clip。
- **真相**：`background-clip:text` 必须独占元素，一个元素只能有一种被裁切的背景。
- **对策**：三层结构 `.titleBadge > i > span`（框/填充/字），一层一职，勿合并。

### 坑 3：删了属性不删死 CSS
- **坑象**：密码框去掉 `placeholder="请输入密钥"` 后，`#bgPwd::placeholder{...}` 规则留在文件里。
- **真相**：规则永不命中，成为死代码；后续改样式时可能被误读为"还有占位符"。
- **对策**：删属性时同步 grep 该选择器全库清理；精准修改 = 连带失效物一起收。

## 二、几何与动画坑（角标四轮迭代的血泪）

### 坑 4：凭单字估计墨迹高度
- **坑象**：防压字常量只测了「师」字覆盖区顶 0.500em（y33），以为够了。
- **真相**：三相位像素测试抓到覆盖区真实最高墨迹是**「多」字左上撇（y17）**，比师字右部高 16px——不动它照样压字。
- **对策**：**墨迹常数必须逐字实测、取覆盖区并集最高列**；改字体/改字号必须重测。

### 坑 5：用 getBoundingClientRect 量浮动中的元素
- **坑象**：角标定位/填充采样用 rect，发现位置和颜色会随浮动相位漂移，间隙忽大忽小。
- **真相**：rect 含动画 transform 的实时位移（±10px）；offsetLeft/Top 是布局坐标，不受 transform 影响。
- **对策**：几何计算与像素采样一律用布局坐标（offsetParent 链）；要量"某一时刻的真实位置"才用 rect，且必须先冻结动画。

### 坑 6：给角标配独立浮动相位
- **坑象**：角标自己 floats，结果和大标题错峰——字浮上来时角标没动，压字；按 ±10px 双程预留空间，矮屏放不下。
- **真相**：挂靠同一浮动体系，**延迟取邻字相位中点** ⇒ 与两字漂移 ≤0.5px ⇒ 相对几何恒定，布局间隙即永恒间隙。这是同时满足「像大字一样浮动」+「任何相位不出框不压字」的唯一解。
- **对策**：同相浮动 + 先读 keyframes 确认是**单向**（只上浮不下沉，比双向少一半约束）再算空间，避免过度预留。

### 坑 7：空间账按理想屏算
- **坑象**：角标在 1440 宽屏验证全绿，1366×768 宽矮屏顶点出框。
- **真相**：「框内沿→多字左上撇墨迹顶」可用带仅 33.9px（1366×768）~39px；角标高 21px，浮动安全位需 12+21+3=36px，差 0.9~2px。
- **对策**：headBlock 垂直 padding 下限 14→20px（`clamp(20px,2.2vh,22px)`）；几何验证必须覆盖 7 视口（含 1366×768 与 390 宽）。

## 三、验证坑（方法自身的坑）

### 坑 8：回归脚本自己的字符串 bug 造成假 FAIL
- **坑象**：断言「角标边框渐变与标语逐字节相同」连续 2 个 FAIL，以为样式真错了。
- **真相**：测试脚本用 `replace(/, /g,',')` 去空格，反而把 getComputedStyle 序列化渐变的格式改坏了，匹配不上；实际样式完全正确。
- **对策**：FAIL 先复看"是产品错还是测试错"；断言要对齐**运行时序列化格式**（源码写法 ≠ computed style 读数）。

### 坑 9：用「无输出」证明干净
- **坑象**：`grep` 没匹配就宣布无残留（如占位符清干净了）。
- **真相**：macOS BSD grep 的 `\|` 不是正则交替（需 `-E`）；无输出可能只是工具不说话。
- **对策**：关键"无残留"断言用两种工具或 `grep -c` 计数复核。

### 坑 10：只测静态不测时序
- **坑象**：截一张静止图看间隙 OK 就收工；浮动起来压字/出框。
- **真相**：浮动体系的坑只在特定相位暴露。
- **对策**：相位扫描（冻结到同一 currentTime 遍历 17 相位）+ 像素逐列间隙 + live 跑满一个周期，三件套一个不能少。

## 四、流程坑

### 坑 11：改完不升 build 戳
- **坑象**：第 15 轮 2 行小改直接发布，线上无法用 build 戳判断版本。
- **真相**：`<meta name="build">` 是线上核验唯一锚点，浏览器缓存还会骗人。
- **对策**：任何改动（哪怕 2 行）发布前必升戳；小改可以借 md5 比对弥补一次，但不许成惯例。

### 坑 12：外部客户端在修复窗口期插 pull
- **坑象**：amend 之后、强推之前，本地冒出个没创建过的 merge 提交。
- **真相**：GitHub Desktop 等外部客户端会在后台 pull；rewrite 历史与远端分叉时，`pull --ff` 退化成 merge，把旧提交合并回来。
- **对策**：`reset --hard <修正提交> && push --force` 一条命令链原子完成；发布/提交前关闭外部 git 客户端的自动同步。
